01 · La App Web

1.1 ¿Para qué sirve esta aplicación en la vida real?

Las apps normales solo muestran el aire actual; AeroGuard avisa con 6 horas de ventaja si se volverá dañino.

¿Qué es aire dañino (PM2.5)?

Polvo y humo ultrafino 30× más delgado que un cabello que entra directo a pulmones y sangre. La OMS fija 15 µg/m³ como límite seguro.

¿Quién usa esta Web?

Municipalidades, colegios y postas médicas para saber con 6h de anticipación si deben suspender actividades físicas al aire libre.

¿Qué hace el usuario?

Elige una ciudad del Perú, ve clima y aire actual desde Open-Meteo, consulta la alerta a +6h y guarda reportes en SQLite.

02 · Metodología CRISP-DM

2.0 ¿Qué significa CRISP-DM y cuáles son sus 6 fases?

Es el estándar mundial de 6 pasos para desarrollar proyectos de Minería de Datos de forma ordenada e iterativa.

Fase 1 Comprensión del Negocio

Definir qué problema real resolvemos y cuál es la meta mínima de éxito.

Fase 2 Comprensión de Datos

Descargar datos reales vía API externa y analizarlos con gráficas (EDA).

Fase 3 Preparación de Datos

Crear variables causales sin fuga de datos y separar pasado vs. futuro.

Fase 4 Modelado

Entrenar y comparar varios algoritmos buscando el mejor equilibrio.

Fase 5 Evaluación

Medir desempeño en meses futuros reales y explicar sus decisiones (SHAP).

Fase 6 Despliegue

Servir el modelo en la App Web con guía reproducible paso a paso.

02 · CRISP-DM · Fase 1 de 6

Fase 1: Comprensión del Negocio

Antes de programar modelos, definimos qué necesita el usuario y cómo sabremos si el modelo funciona.

Objetivo de Negocio (Sistema)

  • Problema: Los monitores actuales solo informan el presente y llegan tarde para proteger la salud.
  • Meta práctica: Alertar con 6 horas de anticipación cuando el PM2.5 vaya a superar 15 µg/m³ (OMS).
  • Trazabilidad: Guardar inspecciones y alertas en una base de datos SQLite.

Objetivo de Minería (Técnico)

  • Tarea ML: Clasificación binaria supervisada (0 = Normal, 1 = Alerta OMS).
  • Criterio de éxito: Alcanzar ROC-AUC ≥ 0.80 en meses futuros reales, superando al modelo base lineal.
  • Explicabilidad: Justificar cada alerta con variables físicas reales vía SHAP.
Evidencia documental: Definido antes del modelado en docs/01_FASE1_Comprension_Negocio.md.

02 · CRISP-DM · Fase 3 de 6

Fase 3: Preparación de los Datos (Sin Fuga de Datos)

Usamos únicamente variables disponibles en ≤ t para predecir si PM2.5(t + 6h) ≥ 15 µg/m³, con corte cronológico estricto.

1. Estado en t (14 vars)

Altitud, 8 climáticas (temperatura, humedad, presión, viento, radiación) y 5 de aire (PM2.5, PM10, NO₂, CO, O₃).

2. Tendencia Pasada (7 vars)

Rezagos de 3h y 6h (pm25_lag3, lag6) más cambios recientes (deltas) en el módulo compartido src/features.py.

3. Hora Cíclica + Ciudad (6)

Seno/coseno de hora y mes (une 23h con 00h) más ciudad y region codificadas dentro del Pipeline.

Fase 6: Despliegue y Reproducibilidad Paso a Paso

El modelo vive dentro de FastAPI + SQLite y cualquier evaluador puede replicar todo en su computadora desde cero.

Terminal · Python 3.12 Replicación completa 
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

# 1. Descargar datos reales de Open-Meteo
python src/extract_data.py

# 2. Generar EDA, entrenar y exportar SHAP
python src/eda.py
python src/train.py

# 3. Ejecutar 7 pruebas y abrir sistema
python -m pytest tests/test_api.py -v
python run_local.py

Garantías de Reproducibilidad

  • Librerías fijadas (==): Versiones exactas en requirements.txt (scikit-learn==1.9.1, fastapi==0.143.0, shap==0.54.1).
  • Linaje SHA-256: Registrado en data/DATA_VERSION.md y dataset_manifest.json con semilla fija SEED=42.
  • Pruebas reales: 7 / 7 tests pasando en pytest (Dashboard, Open-Meteo, HTTP 422 y SQLite).

Ejecución Rápida en Windows

Incluye ABRIR_SISTEMA.bat, EJECUTAR_PRUEBAS.bat, REENTRENAR_MODELO.bat y ABRIR_PRESENTACION.bat.
